# 插画元素拆分与补全

把复杂插画转换成一组可独立使用的视觉素材。先定义元素粒度和补全边界，再逐项编辑、技术检查和成品整理；不要把“AI 重新画了一张相似图”冒充成原画抠图。

## 核心原则

1. **区分提取与重建。** 原图中可见的部分属于保真区域；被遮挡、相互粘连或超出画面的部分属于重建区域。
2. **锁定可见设计。** 保留可见轮廓、五官、姿势、比例、配色、纹样、笔触、水彩晕染和纸面颗粒。只在缺失区域补画。
3. **承认工具边界。** 没有像素级蒙版时，生成式编辑可能重画可见区域。发现漂移时明确标为“AI 重建版”，不要声称像素级忠实。
4. **一项一图。** 每个最终元素单独生成和保存；不要把联系表、编号图或整页贴纸当作独立主素材。
5. **真实透明。** 棋盘格图案不等于透明背景。用脚本检测 Alpha，检测通过后才称为透明 PNG。
6. **制造参数不猜。** PNG、白边和 300 DPI 元数据不能替代供应商要求的矢量刀线、出血或专色白墨。用户准备下单时再索取具体模板。

## 工作流

### 1. 检查原图

- 把上传图标记为编辑目标，不要只作为宽泛风格参考。
- 用原始清晰度查看图片；记录扫描倾斜、纸张底色、阴影、污点、压缩、裁切和分辨率问题。
- 判断媒介：水彩、彩铅、马克笔、油画棒、线稿或数字绘画。
- 对水彩尤其保留半透明淡彩、颜料颗粒和不规则软边；不要用硬阈值把浅色洗掉。

### 2. 建立元素清单

先列出编号、名称、层级、可见状态和补全置信度，再开始批量生成。

采用以下粒度：

- **A 主体元素：** 角色、动物、主要植物、灯具、交通工具、主要商品或其他可独立成图的视觉焦点。
- **B 次要元素：** 花束、餐具、瓶罐、家具、招牌、包袋等具有清晰整体轮廓的道具。
- **C 微型元素：** 单朵花、单片叶、徽记、文字碎片、重复小饰物等。

用户只说“全部元素”而画面十分复杂时，默认列出 A+B，排除墙地顶、大片建筑背景、光影、污渍、纸纹和无意义碎片。把天然形成完整设计的组合视为一个元素，例如“一束花”而不是每片花瓣。若不同粒度会把十几张输出变成数十张，先给出数量估计并让用户选择。

清单至少包含：

| 字段 | 内容 |
|---|---|
| ID | 稳定编号，如 A01、B03 |
| 元素 | 可识别名称和画面位置 |
| 状态 | 完整 / 被遮挡 / 与其他元素粘连 / 被画面裁切 |
| 保真区 | 原图中必须锁定的可见特征 |
| 补全区 | 只允许推断的缺失部分 |
| 置信度 | 高 / 中 / 低 |

### 3. 规划补全

- **高置信度：** 轮廓连续、对称关系或重复结构足以判断缺失部分。直接保守补全。
- **中置信度：** 姿势或结构基本明确，但手脚、背面或局部纹样缺失。采用最简单且符合上下文的方案。
- **低置信度：** 超过约 40% 的关键结构不可见、身份特征被挡、隐藏文字无法确认或存在两种同样合理的结构。输出两种补全方案，或只针对真正影响设计的选择询问用户。

不要凭空添加饰品、花纹、文字、道具或叙事动作。对隐藏文字不要猜字；保留可见文字，缺失处标记为需人工确认。

### 4. 逐项生成

需要实际位图编辑时，使用可用的图像生成/编辑工具。若原图有本地路径，先查看原图，再把它作为编辑目标传入。每个元素单独调用一次；多种不同元素不要用同一个提示词批量替代。

每次调用前读取 [references/prompt-template.md](references/prompt-template.md)，并明确写出：

- 目标元素及其在原图中的位置；
- 可见部分的保真边界；
- 被遮挡或裁切部分的补全边界；
- 原始媒介、笔触、颗粒、色彩和轮廓；
- 单元素、完整轮廓、四周留白、无场景碎片；
- 真实透明背景，禁止绘制棋盘格。

保持原视角和原姿势，除非用户明确要求改姿势。完成被遮挡的手脚时，优先使用自然、简单、不会改变角色性格的姿态。

### 5. 做视觉检查

逐项对照原图检查：

- 五官、表情、头身比、姿势和朝向是否漂移；
- 服装轮廓、花纹、配色和小配件是否被改写；
- 水彩淡色、晕染、纸纹和手绘边缘是否被数字化或过度锐化；
- 补全部分是否符合已知结构，是否出现多肢、断肢、重复耳朵或粘连；
- 是否残留桌椅、植物、人物、文字或其他背景碎片；
- 是否完整显示且四周有安全边距。

一次只修正一个主要问题，并在每轮重复关键保真条件。

### 6. 验证透明通道

运行脚本前，把本 `SKILL.md` 所在目录作为相对路径基准；不要假设当前工作目录就是 Skill 目录。

对每张候选 PNG 运行：

```bash
python3 scripts/inspect_cutout.py candidate.png
```

只有 `valid_transparency` 为 `true` 才能把文件称为透明底素材。若结果是 RGB、Alpha 全不透明或背景只是棋盘格图案：

1. 先要求图像工具只修正真实透明通道，不重画主体；
2. 再次运行检测；
3. 若仍失败，优先重新生成在纯色、与主体颜色明显不同的背景上；
4. 仅把 [scripts/key_background.py](scripts/key_background.py) 作为受控后处理，并在深色、浅色底上检查边缘光晕。

不要对原始水彩扫描图直接自动去白；这会误删淡彩。`key_background.py` 只处理已经生成的单元素纯色或伪棋盘格背景图。

### 7. 整理成品

先保留一份不加白边的透明母版。需要贴纸或冰箱贴预览时，再运行：

```bash
python3 scripts/prepare_cutout.py master.png sticker.png \
  --padding 96 --outline 40 --dpi 300
```

- `--padding`：透明安全边距，单位为像素。
- `--outline`：白色外轮廓宽度，单位为像素；设为 `0` 可只裁切和留边。
- `--dpi`：写入分辨率元数据，不会凭空增加真实细节。

阅读 [references/production-spec.md](references/production-spec.md) 确认文件命名、尺寸换算和商品化限制。

### 8. 交付

按清单编号命名，例如：

- `A01-gray-character-master.png`
- `A01-gray-character-sticker.png`

交付时说明：

- 哪些区域来自原图，哪些区域由 AI 补全；
- 补全置信度和仍需人工确认的地方；
- 是否通过真实 Alpha 检测；
- 是否添加白边、边距和 DPI 元数据；
- 是否仍需供应商刀线或出血模板。

复杂图片分批处理时保持编号不变，不因生成顺序改变名称。

## 失败判定

出现以下任一情况时不要宣布完成：

- 可见区域的身份、五官、纹样或比例明显改变；
- 用相似风格重画取代了原画提取，却未明确说明；
- 输出只有棋盘格视觉效果，没有真实 Alpha；
- 浅色水彩边缘被切掉或带明显白灰光晕；
- 元素没有补全、仍被裁切或混入其他场景内容；
- 分辨率和供应商要求未经确认却声称可直接量产。
